# 视觉主题使用与发布指南

本文面向 Wristo 表盘设计师和发布运营人员，说明如何创建、检查和发布 Visual Themes（视觉主题）。Studio 中面向设计师的说明使用中文；写入 Garmin Connect IQ 设置并展示给最终用户的主题名称和标签应使用英文，例如 `Theme`、`Classic`、`Night`。

## 功能边界

视觉主题是在同一套表盘布局上切换一组协调的视觉资源。一个主题可以包含背景、时针、分针、秒针、中心盖，以及由主题管理的现有颜色属性。主题不会改变字体、元素位置、数据字段、元素显隐或布局。

每个设计最多保存 5 个主题。主题在列表中的顺序会成为 Garmin 设置中的数值索引和打包资源顺序，因此已发布产品应保持已有主题的顺序和 ID 稳定，只在末尾追加新主题。重命名不会改变主题 ID；复制主题会生成新 ID。

## 设计操作

1. 在 Studio 的全局视觉主题面板启用视觉主题。旧设计首次启用时，Studio 会根据当前背景、指针和中心盖创建一个默认主题，不会改写基础元素。
2. 为每个主题填写唯一的英文名称，并选择默认主题。名称最长 24 个字符。
3. 为每个主题选择时针和分针，这两项是必需项。背景、秒针和中心盖可以留空，并按“主题资源 → 对应基础元素资源 → 不生成该资源”的顺序回退。
4. 根据需要新增、复制、重命名、删除主题或调整顺序。删除默认主题前，必须先指定另一个默认主题。
5. 使用预览主题检查整体效果。预览选择只影响编辑器，不会改变发布时的默认主题。

主题素材必须保存持久化 `assetId` 和可长期获取的原始文件引用。`blob:` 预览地址不是可打包来源；即使画布当前可见，也不能把浏览器临时地址当作素材记录。指针选择必须保留原始 SVG/文件引用，不能只保留 PNG 预览。

## 颜色属性

视觉主题复用现有颜色属性，不创建另一套颜色变量。颜色属性的 `themeMode` 决定归属：

- `theme`：值由当前视觉主题提供，不再作为独立 Garmin 颜色设置输出。
- `user`：值继续由 Garmin 用户设置控制，视觉主题不能覆盖。
- 未设置 `themeMode`：按 `user` 处理，以兼容旧设计。

同一个颜色属性不能同时由视觉主题和用户设置控制。发布前应逐项确认主题颜色只引用已经存在且 `themeMode=theme` 的颜色属性。

## 与动态主题规则的关系

Visual Themes 与 Dynamic Theme Rules（动态主题规则）在首个版本中互斥，因为两者都会控制背景或颜色：

- 已启用动态主题规则时，不能启用视觉主题。
- 已启用视觉主题时，不能启用动态主题规则。
- Studio 无法确认动态规则状态（例如接口加载失败）时按失败关闭处理：不得启用冲突功能，也不得假定当前无动态规则。
- 停用任一功能始终允许，以便解除冲突。

动态规则不会在本版本中选择 `visualThemeId`。

## 模拟表盘素材生命周期

模拟表盘素材在全局范围只停用，不物理删除：

- Studio 的新素材选择默认只显示启用中的素材。
- 停用不会删除素材记录、存储文件或已有设计引用。
- 已保存设计仍可按素材 ID 获取停用素材，历史设计和打包流程可以继续解析它。
- 管理员可以在管理接口中显式查询停用素材，并通过明确设置 `isActive=true` 重新启用。
- Studio 用户不能停用系统素材，只能停用自己拥有的素材；管理员权限按服务端规则执行。

因此，不要通过替换数据库记录或删除存储文件来“清理”主题素材。需要停止新设计继续使用时，应停用原素材；需要恢复选择时，由管理员显式重新启用。

## 低功耗与低端设备

支持 `AffineTransform` 的设备使用主题位图指针；不支持的设备继续使用几何指针回退，并采用当前主题配置的时针、分针和秒针回退颜色。几何回退只保证可读性，不保证复刻位图形状。

首个版本不提供每主题独立 AOD 素材。AOD 继续使用现有低功耗和防烧屏路径：秒针可能被隐藏或简化，缺失秒针和中心盖时不会自动补造资源。设计师必须分别检查亮屏与 AOD，尤其注意对比度、残影风险和几何指针的可读性。

## 包体与运行时约束

打包会包含所有已发布主题的资源，但运行时只加载当前主题。主题越多、位图尺寸越大、透明度和颜色越复杂，包体和设备资源压力越高；“最多 5 个主题”不是包体安全保证。

发布前应使用目标设备矩阵进行真实 Connect IQ 编译和包体/内存检查，并优先压缩背景和指针素材。仅通过 Studio 构建、Python 单元测试、模板渲染或 Shell 语法检查，不能证明 Monkey C 可编译、设备可安装或运行时内存满足限制。

## 发布前验证

按类别分别记录结果，不要用一类检查代替另一类：

### Studio

- 完整运行 `npm run test:unit` 和 `npm run build`。
- 检查启用、复制、重命名、删除、排序、默认主题和预览切换。
- 保存并重新打开设计，确认主题 ID、顺序、默认值、`assetId`、原始文件引用和 `themeMode` 未变化。
- 验证最多 5 个主题、必需的时针/分针和 `blob:` 拒绝逻辑。

### API 与素材生命周期

- 运行视觉主题配置往返测试，以及模拟素材停用、默认列表过滤、历史 ID 获取和管理员重新启用测试。
- 确认停用操作没有删除素材行、收藏关系、文件记录或对象存储文件。
- 记录完整 Maven 测试是否执行；只运行定向测试时必须明确标记为局部证据。

### Scaffold 与模板

- 运行视觉主题提取、资源转换、模板渲染和旧设计兼容测试。
- 运行完整 Python `unittest` discovery，并将缺少 `jinja2` 或 `jinja2-cli` 导致的环境失败单独报告。
- 对 scaffold 中所有 Shell 脚本运行 `bash -n`。
- 核对 SuperAlpha 模板与 scaffold 测试快照一致。

### Connect IQ、设备与部署

- 使用真实 Connect IQ SDK 编译目标产品和目标设备。
- 检查首次安装默认主题、设置中的英文名称、切换、非法索引回退、AOD、低端设备几何指针和包体/内存。
- 如未执行上述步骤，发布记录必须写明“无 Monkey C 编译、设备、安装和部署证据”，不得由其他测试推断通过。

## 当前发布安全说明

视觉主题运行时依赖 `wristo-apps/SuperAlpha` 中的模板文件。若这些模板在该仓库中仍显示为未提交修改，或因仓库/元数据权限无法形成提交，则 Studio、API 和 scaffold 的测试通过也不代表可复现发布。发布负责人必须先确认 SuperAlpha 模板已进入可追踪的提交，并记录对应提交号，再进行正式 Connect IQ 编译与部署。
