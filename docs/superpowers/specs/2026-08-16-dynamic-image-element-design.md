# 动态图片元素设计

## 背景

Studio 目前通过多个独立 `image` 元素叠放在同一位置，并分别配置动态可见性，来实现天气背景、状态图标等素材切换。该方式可以运行，但会重复维护位置和尺寸，图层数量多，也无法明确表达素材之间“只显示一个”的互斥关系。

本设计新增独立的 `dynamicImage` 元素。它在一个公共画框中维护多个“表达式 → 素材”候选项，运行时按顺序选择并绘制一张图片。

## 目标

- 用一个图层表达同一位置上的动态图片切换。
- 所有候选素材共享位置、宽高、旋转、透明度和缩放模式。
- 按候选项顺序选择第一个表达式成立的素材。
- 支持可选默认素材；未命中且没有默认素材时隐藏。
- Studio 预览、设计保存、WRT 打包与 Connect IQ 运行时保持相同语义。
- 不改变现有 `image` 元素或旧设计数据。

## 非目标

首版不支持：

- 将多个已有 `image` 元素批量转换成动态图片。
- 为候选素材设置独立位置、尺寸、旋转、透明度或缩放模式。
- 同时绘制多个命中的素材。
- 动态图片嵌套动态图片。
- 在候选项中混合图片、文字、图形等不同元素类型。
- 在图层面板中把每个候选素材显示为独立子图层。

## 元素模型

UI 名称为“动态图片”，内部元素类型为 `dynamicImage`。

```ts
interface DynamicImageElementConfig extends BaseElementConfig {
  eleType: 'dynamicImage'
  width: number
  height: number
  fit: 'contain' | 'cover' | 'stretch'
  items: DynamicImageItem[]
  defaultAsset?: DynamicImageAsset
}

interface DynamicImageItem {
  id: string
  name?: string
  imageUrl: string
  assetId?: number
  expression: DynamicExpression<boolean>
}

interface DynamicImageAsset {
  imageUrl: string
  assetId?: number
}
```

候选项数组的存储顺序就是匹配优先级。候选项只能拥有素材、名称和表达式；布局字段只能存在于外层元素。

`fit` 默认值为 `contain`：

- `contain`：完整显示素材，允许画框内留空。
- `cover`：填满画框，允许裁切素材。
- `stretch`：强制填满画框，允许改变素材比例。

## 运行语义

1. 先计算元素继承自 `BaseElementConfig` 的外层动态可见性。
2. 外层不可见时不计算内部候选项，也不绘制图片。
3. 外层可见时，从上到下计算候选表达式。
4. 第一个结果为 `true` 且素材可用的候选项胜出，后续候选项不再计算。
5. 表达式为 `false`、数据不可用或计算异常时，将该项视为不命中并继续下一项。
6. 表达式成立但素材加载失败时，继续查找后续可用的命中项。
7. 没有可用候选项时使用 `defaultAsset`。
8. 没有可用候选项且未配置默认素材时不绘制元素。

运行时缓存上次选中的候选项索引。只有选择结果发生变化时才切换 bitmap，避免重复加载相同资源。

## Studio 交互

### 添加和图层

顶部“添加元素”增加“动态图片”。动态图片在图层面板中始终显示为一个普通元素，例如“天气背景”。首版不在图层面板展开候选素材。

### 公共布局

属性面板复用普通图片的位置、宽高、旋转和透明度编辑能力，并增加统一的 `Contain`、`Cover`、`Stretch` 缩放模式。所有候选素材和默认素材使用同一个画框与缩放规则。

### 动态素材列表

每个列表项包含：

- 拖拽排序手柄。
- 素材缩略图。
- 可选名称。
- 表达式摘要。
- 编辑、复制和删除操作。

展开列表项后可以选择或上传素材，并使用现有表达式编辑器配置布尔表达式。列表上方显示固定说明：“按从上到下的顺序匹配，只显示第一个符合条件的素材。”

Studio 根据当前模拟数据立即计算命中结果，并在列表中标记“当前命中”。修改候选顺序、表达式、素材或模拟值后重新计算。

### 默认素材

列表底部提供独立的“默认素材”区域。默认不配置；用户可以选择、上传、替换或清除默认素材。

### 隐藏时编辑

动态图片被选中时，即使当前没有命中项，也保留可选择的画框占位，避免隐藏后无法继续编辑。取消选择后按真实运行规则隐藏。

## Studio 架构与数据流

- 在元素类型联合、类型映射、插件注册和添加元素入口中注册 `dynamicImage`。
- 新增独立的动态图片 panel、renderer 和 encoder，避免把普通 `image` 改造成双模式元素。
- renderer 复用普通图片的加载和尺寸适配能力，但画布上只维护一个 Fabric 对象。命中项变化时替换该对象的图片源，不创建多个叠放对象。
- 候选表达式使用现有统一动态表达式解析、Token 预览和模拟数据能力。
- 保存前递归持久化候选素材及默认素材的 `blob:` URL。
- 导出校验复用现有表达式校验能力，并把错误定位到动态图片名称和候选项名称或序号。

## 保存与导出校验

保存的数据保留候选项顺序。导出前必须满足：

- 至少存在一个候选项。
- 每个候选项都有唯一且非空的 `id`。
- 每个候选项都有可持久化的素材。
- 每个候选项都有合法的布尔表达式。
- 默认素材如果存在，也必须可以持久化。
- `width` 和 `height` 为有效正数，`fit` 为受支持的枚举值。

非法表达式、缺失素材或持久化失败会阻止导出，错误信息必须指出具体候选项。普通 `image` 和旧设计不做迁移，也不改变其校验规则。

## Connect IQ 构建链路

构建端新增对 `dynamicImage` 的提取与模板支持：

1. 收集全部候选素材和默认素材，生成稳定且唯一的资源 ID。
2. 按数组顺序编译每个候选表达式。
3. 汇总所有表达式引用的数据字段，供运行时数据提供器生成和裁剪逻辑使用。
4. 先应用元素外层动态可见性，再按候选顺序执行短路匹配。
5. 只绘制最终选择的 bitmap，并应用公共位置、尺寸、旋转、透明度和缩放规则。
6. 保留上次命中索引，结果没有变化时复用已选择资源。

Studio 和构建端必须共享以下契约：首个命中优先、失败继续、默认素材可选、无结果时隐藏。

## 异常处理

- 数据不可用：候选项视为不命中。
- 表达式计算异常：候选项视为不命中，不中断后续匹配。
- 候选素材加载失败：继续检查后续命中项。
- 默认素材加载失败：元素不绘制。
- 多个表达式同时成立：按列表顺序选择第一项。
- 没有表达式成立：显示默认素材；未配置默认素材时隐藏。

Studio 预览可以记录或展示非阻塞诊断信息，但上述运行时容错不能掩盖导出阶段可提前发现的配置错误。

## 测试与验收

### Studio

- 元素注册、编码、解码与保存后重新打开。
- 候选项首个命中和短路计算。
- 多个表达式同时成立时的列表优先级。
- 排序后命中结果立即变化。
- 默认素材存在、不存在和加载失败的行为。
- 数据不可用、表达式异常和候选素材失败后的继续匹配。
- 外层动态可见性优先于内部候选项。
- 被选中且无匹配时保留编辑画框，取消选择后隐藏。
- `contain`、`cover` 和 `stretch` 的公共布局效果。
- 候选素材及默认素材的 blob 持久化与 WRT 资源打包。
- 非法表达式和缺失素材阻止导出，并定位到具体候选项。
- 普通 `image` 与旧设计行为不变。

### Connect IQ 构建

- 提取器保留候选顺序并收集全部表达式字段。
- 生成的 Monkey C 使用首个命中优先的短路逻辑。
- 数据不可用、表达式异常和素材不可用时正确回退。
- 默认素材和无默认素材两种路径。
- 外层动态可见性阻止内部选择和绘制。
- 命中索引不变时不重复切换 bitmap。
- 不同设备和显示模式下资源生成与绘制正常。

### 验收场景

用一组天气背景素材创建单个动态图片：多条天气表达式中即使存在重叠，也只显示列表中的第一个命中项；调整模拟天气代码后画布立即切换素材；未知天气显示可选默认素材，清除默认素材后隐藏；保存、重新打开并构建 PRG 后，设备运行结果与 Studio 预览一致。
