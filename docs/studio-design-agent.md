# Wristo Studio 表盘设计 Agent 规格

## 目标

在 Wristo Studio 内提供对话式表盘创作 Agent。用户可从空画布生成完整设计，也可用自然语言增量修改当前设计。Agent 仅使用 Studio 已有元素、字体、数据类型与素材；所有修改必须先预览、后确认，并可作为一个整体撤销。

第一版不生成 SVG 或 AI 图片，不上传新素材，不自动保存、发布、构建 IQ 包或操作产品数据。

## 核心原则

- 模型输出受约束的语义化设计补丁，不直接生成或修改 Fabric 对象。
- Studio 使用确定性编译器把设计补丁转换为真实 `RuntimeDesignConfig`。
- 候选配置通过结构、业务和现有导出校验后才能进入预览。
- 用户确认前不修改正式画布、Store 或服务端设计。
- 一轮已确认的 Agent 修改对应一个原子历史记录，可一次撤销。
- API Key 仅保留在 Wristo API，不能进入浏览器。

## 系统架构

### Studio

- `AgentChatPanel`：承载消息、示例提示、生成状态、重试和错误展示，不直接修改画布。
- `designContextSerializer`：从当前 `RuntimeDesignConfig` 提取模型所需上下文，包括画布规格、元素、位置、样式、数据绑定和可用能力；排除 Fabric 内部状态。
- `designPatchSchema`：定义客户端可接受的补丁版本、操作和字段白名单。
- `designPatchCompiler`：解析语义位置，补齐默认值和 ID，生成候选运行时配置。
- `DesignChangePreview`：显示候选画布以及新增、修改、删除分组。
- `designPatchExecutor`：在用户确认后原子应用候选配置，并写入一次历史快照。

### Wristo API

- `DesignAgentController`：提供鉴权后的对话接口。
- `DesignAgentService`：构建提示词、裁剪上下文、调用 OpenAI Responses API、解析结构化输出并执行服务端校验。
- API 复用现有 OpenAI 基础配置方式，但为设计 Agent 使用独立的模型和输入输出限制配置。
- 对话请求携带最近有限轮次，不在第一版建设长期记忆、向量检索或独立 Agent 数据库。

## 请求与响应

请求包含：

- 本轮用户指令；
- 当前设计的精简快照和摘要版本；
- 最近若干轮已确认对话；
- Studio 支持的元素、字体、格式和数据绑定能力清单；
- 目标设备画布的宽、高和形状。

响应包含：

- 面向用户的简短说明；
- 变更摘要；
- 符合版本化 Schema 的设计操作列表；
- 可选的安全调整说明或不可执行原因。

模型不返回 Fabric 序列化对象，不直接写数据库，也不能触发保存、发布、构建或上传。

## 设计补丁协议

顶层结构：

```json
{
  "version": "1.0",
  "summary": "创建黑底荧光绿运动表盘",
  "assistantMessage": "我会突出时间，并在底部加入步数和心率。",
  "operations": []
}
```

第一版允许以下操作：

- `add`：增加能力清单内的现有元素。
- `update`：修改样式、格式、尺寸或数据绑定。
- `move`：按绝对值或语义位置移动元素。
- `remove`：删除元素，仅在用户明确要求删除、替换或重新设计时允许。
- `reorder`：调整图层顺序。
- `setDesign`：修改背景、名称和允许的设计级显示设置。

新增元素使用本轮唯一的 `clientRef`；Studio 编译时分配正式元素 ID。修改现有元素必须引用当前精简快照中的稳定 ID。

模型优先使用 `center`、`top-right`、`bottom-left`、`below:<ref>` 等语义位置。编译器根据设备画布换算坐标，执行边界检查，并对明显越界或严重重叠进行安全调整。调整结果必须在预览说明中展示。

未知元素、未知字段、不可用字体、非法格式、无效绑定或未获授权的删除操作均应被拒绝。

## 对话与预览流程

1. 用户在 Studio 右侧 Agent 面板输入指令。
2. Studio 生成当前设计摘要版本并发送精简上下文。
3. API 调用模型并验证结构化补丁；格式错误时最多自动修复一次。
4. Studio 再次校验补丁，并在隔离状态中编译候选配置。
5. 候选配置通过现有配置、数据绑定和导出校验。
6. Studio 显示候选画布和变更列表：绿色表示新增，蓝色表示修改，红色表示删除。
7. 用户选择 `Apply changes` 或 `Discard`。
8. 应用时检查设计摘要版本是否仍一致；若画布已变化，则要求基于最新状态重新生成。
9. 确认后的候选配置原子写入画布和相关 Store，并形成一个历史记录。
10. 用户可继续对话；保存仍通过 Studio 现有 Save 流程完成。

## 从零创作与增量修改

空画布请求可以生成一组 `setDesign` 和 `add` 操作，形成完整表盘。

已有设计请求默认只返回必要的 `update`、`move`、`add` 或 `reorder` 操作。未被补丁命中的元素及字段必须保持不变。除非用户明确要求重新设计或删除，否则不得用完整配置覆盖现有设计，也不得移除已有元素。

## 错误处理

- 模型格式错误：服务端尝试一次结构化修复；失败后返回可重试错误。
- Schema 或业务校验失败：不创建候选画布，并指出具体操作和字段。
- 编译失败：保持正式画布和 Store 不变。
- 网络失败或超时：保留用户输入并允许重试。
- 摘要版本冲突：废弃候选结果，基于最新画布重新生成。
- 服务未配置或额度不可用：禁用提交并显示状态，不影响 Studio 其他编辑能力。
- 单个操作不可执行时，第一版拒绝整份补丁，避免部分应用造成设计语义不完整。

## 安全与限制

- 接口必须使用现有 Studio 用户鉴权，并设置请求频率、输入长度、响应大小和超时限制。
- 服务端提示词和 Schema 将用户文本视为设计意图，禁止其扩大工具权限。
- 第一版不给模型提供任意 URL、文件、上传、数据库、发布或构建工具。
- 发送给模型的配置必须裁剪，不包含用户隐私、令牌、素材二进制内容或无关产品数据。
- 日志记录请求 ID、耗时、模型和错误类型，不记录密钥；用户提示词与设计内容的保留策略应沿用 Wristo 的隐私约定。

## 测试与验收

### Studio 单元和集成测试

- Schema 接受合法补丁并拒绝未知字段、未知元素、非法绑定和危险删除。
- 编译器覆盖圆形和方形画布、语义坐标、归一化、ID、层级和默认值。
- 增量补丁不会修改未命中的元素与字段。
- 编译或应用失败不会产生部分画布或 Store 更新。
- 一轮 Agent 修改可一次 Undo。
- 覆盖空白创作、修改现有设计、丢弃预览和摘要版本冲突。

### API 测试

- 覆盖鉴权、结构化响应解析、自动修复一次、超时、错误映射和输入限制。
- 使用桩响应验证提示词与补丁协议，不在常规测试中调用真实模型。

### 完成标准

- 用户可在空画布输入自然语言并看到合法候选表盘。
- 用户可对已有设计进行连续增量修改。
- 未确认的候选结果不污染正式设计。
- 应用操作可整体撤销，设计可继续通过现有 Save 与导出流程处理。
- Studio 针对性测试与构建通过，Wristo API 相关 Maven 测试通过。

本地测试和构建不能证明真实 OpenAI 配置、生产网络、Garmin Simulator、硬件设备、Build IQ、发布或安装交付；这些需要独立验证。
